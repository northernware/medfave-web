# Breadcrumbs are now one back link, to where you came from

The trail above pages ("Patients › Patient › Edit") is gone. It was built from the address, so it repeated the page title ("New" over "Add patient"), used URL words, and led somewhere other than where you'd been: open a patient from Today, follow the trail back, and you landed in the Patients list.

Now there is one link, "‹ Today", named after the page you came from. It really goes back (`router.back()`), so that page keeps its scroll and filters.

- **Where you came from:** a short trail of pages kept in this tab's `sessionStorage` (`medfave.trail`). Arriving where you just were counts as going back; anything else is a step forward. Each page is named after its section (Today, Patients…) or its title.
- **Opened cold** (a link, a refresh, a new tab): falls back to the page above, the patient for an edit and so on, named with `CrumbName`. The patient edit pages (doctor and desk) now pass the name.
- **A note opened in the side panel** over Today doesn't count as a page: the path comes from `useSelectedLayoutSegments`, not the address.
- **Section pages** (Today, Patients…) still show nothing. On form and note pages the link sits over the centred column.

Code: `components/breadcrumbs.tsx` (the name `Breadcrumbs` is kept, so the shell is unchanged).

## Follow-up: notes go back to their patient

A note's address has no patient in it, so opened cold it had no back link. Pages can now name the page above them with `<BackTo href label />` (`components/crumb-names.tsx`); `NoteHeader` (new note, draft, amend) and the full note page use it, giving "‹ the patient's name". Where you came from still wins when there is one.
