# Unit tests for the visit day's rules

Opened: 2026-10-05 21:31 PHT

## What
- `npm test` runs Vitest (`vitest.config.mts`, files `lib/**/*.test.ts`). 13 tests:
  - `lib/visit-day.test.ts`: the "I'll be there" window, the upcoming/past split on the visit day, held slots after an early check-in, the doctor's queue order;
  - `lib/domain.test.ts`: `movesFrom` (late check-in, restore only while due).
- The pure parts moved to `lib/visit-day.ts` (no database, no `server-only`), so they can be tested: `confirmWindow`, `canConfirm`, `CHANGEABLE`, `splitVisits`, `heldFrom` and `queueOrder`. `lib/patient-visits.ts` re-exports the first three; `heldSlots`, `GET /patient/appointments` and `GET /doctor/day` call them. Behaviour is unchanged.

## Why
Plan *mobile-next*, step E: these rules were only checked by one-off scripts.

## Tested
- `npm test`: 13 passed. `tsc` (apart from the missing `@solar-icons/react` install) and eslint clean.
- Against the local server, `/doctor/day` and `/patient/appointments` return the same shapes and order as before.

## Heads-up
- New dev dependency: `vitest@^4.1.11`. Vitest 5 needs a newer `@types/node` than the project resolves.
- Put new pure rules in `lib/visit-day.ts` (or another file without `server-only`) with a `.test.ts` beside them.
